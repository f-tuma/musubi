# MUSU-40 · Remaining event lifecycle

This records the pre-policy extraction and the following Google RSVP policy
change. Combined source, local-installed and final application/browser acceptance
pass in the bounded scope of the [C08 audit](MUSU-40-acceptance.md). Final PR/tree
review, current-head checks and main verification remain pending. The lifecycle
is shared host compatibility with its existing provider capability floor;
registry publication and production deployment remain separate.

The immutable old executor is `event_delivery.ts` at
`8ea0d3bfe193abd701e06c15d19b5d312bdd2290`, SHA256
`63f478c91e36db4913717db759e773d260e928cc530dd0c8696112b5e39ae8b0`.
The API keeps claim/decode, present pinned validation and the exact existing
portable Google/Graph/DAV precedence. Its host bridge keeps native evidence
parsers/serializers, source/privacy/lease and feature authority, full DAV resource
contexts, family/notification journals and atomic DB completion. Native adapters
remain the actual existing production implementations.

`runClaimedEventCompatibility` owns one remaining lifecycle under one attempt
deadline/heartbeat, with typed preparation, confirmation, possible-dispatch and
acceptance callbacks, native reads/writes, proof comparisons, recovery, conflict
observation and completion ports. It does not execute an opaque orchestration
callback. Attempt-local full family/organizer observations stay behind the host
ports; a failed Graph family CREATE never invents a master-only result reference.

Actual priority remains Graph occurrence content, Graph meeting cancellation,
organizer, instance reminders, Graph family deletion, Graph family creation, DAV
alarms, DAV split, DAV whole-series deletion, DAV scoped-series write, Google
occurrence, Microsoft/DAV/Google RSVP, one-off reminders, then generic fallback.
Multiple keys retain that original first matching family. The exclusion array

The generic profile includes retained Google, Graph and DAV CREATE/UPDATE/DELETE.
It preserves legacy all-day/unknown time metadata while refusing every known
zoned/all-day/floating model before native preflight, including DELETE without a
target. Reserved top-level `timeEdit` and `graphOccurrence` remain admission and
selection guards, not new writers. Existing selectors retain their original
differences. Real Graph occurrence writes use `graphOccurrenceContent`; nested
RSVP occurrence proof is independent.

The claim's recovery flags, original host row, feature decisions, full prepared
data, refs, original occurrence slots and historical resource/family evidence
are owned before yielding. The descriptor copier preserves Dates, undefined and
legacy data size/depth floors, refusing accessors/callbacks without evaluating
them. Native calls receive separate mutable data copies; preflight cannot replace
the writer's original canonical values or milliseconds. A closed attempt cannot
enter another writer/callback/ACK. A returned committed completion remains the
host authority when cancellation races its response.

Historical `mutationStarted` remains pessimistic uncertainty control. DAV
split/series/deletion mark it before native execution, and some recovered proofs
set it without a current write. It is distinct from complete writer fulfillment,
concrete native acceptance callbacks, durable possible-notification markers and
notification delivery, which remains unknown.

At the immutable pre-policy extraction checkpoints, Google RSVP had an explicit
C08 policy gap. That historical parity extraction preserved
its actual desired-result GET first, followed by another original strong
If-Match PATCH with `sendUpdates=all` when the entire current object still equals
the saved baseline, even on a reconciling row. Graph RSVP's permanent
`graphDispatch` and DAV's missing/started historical `caldavDelivery` retain their
existing observe-only policies. An irreversible Google barrier belongs to the
separate following policy gate; historical parity is not a blanket no-resend claim.

The combined source now includes that separate policy gate. New Google RSVP
admissions carry a strict private `googleDelivery` sidecar. The host consumes
its write permission durably before PATCH, under the original current claim,
source, privacy and OAuth grant. Started and markerless legacy operations only
observe; same-intent manual retry never synthesizes permission. A fully desired
observation may complete, while notification delivery stays unknown. False
marker authority and an ambiguous COMMIT remain different uncertainty facts.
An explicit new resolution operation may receive a fresh sidecar under its own
fresh baseline/source/actor guards; it does not reset permission on the original
consumed or markerless operation. Recovery of that original row stays read-only.

Event ACK cancellation also retains existing host API capability. Ordinary
legacy completion did not pass its optional AbortSignal; specialized completion
APIs expose no signal parameter. A runtime guard before entry does not prove
rollback during an already entered DB lock/pool wait. This is a retained host
capability limitation, not a new cancellation guarantee. Existing lease/source
and committed-ACK authority remain in force. The protected bounded portable
Google route retains its separate waiting-ACK rollback guarantee; task ACK has
its own independently proved signal guards.
