# Musubi 0.2.7 release notes

This API/web diagnostic hotfix distinguishes Microsoft To Do task-read HTTP
failures by request phase. Live 0.2.6 verification restored calendar window
reads, while the separate `Skip token is not provided` HTTP 400 continued in
the task-delta path. Existing logs do not establish whether its request used
initial parameters, a saved cursor, or a returned next link.

Task delta and snapshot HTTP failures now retain a fixed error classification,
read kind, request phase, numeric HTTP status, allowlisted Graph error-code
classifications, and the presence or multiplicity of recognized continuation
parameters. Diagnostics contain no request URL, task-list identity, parameter
values, provider message, response body, or raw caught error. Optional-task 403
and transient-status handling continue to use the existing Outlook status
prefix. Other Graph operations retain their existing error behavior.

Request URL/query bytes, success results, checkpoint selection, pagination,
unsupported-delta snapshot fallback and existing 410 recovery are unchanged.
This release adds evidence for selecting a recovery fix; it does not claim to
resolve the remaining task HTTP 400. The old provider-message substring is
replaced by a fixed task-read message: monitor the structured
`graph-task-read-http-failed` cause and HTTP status rather than interpreting the
old substring's disappearance as recovery.

## Upgrade and acceptance

There is **no new database migration relative to 0.2.3–0.2.6**. The source
journal still ends at `0085_graph_read_coverage`; client and peer minimums stay
at 0.2.0. Provider gates, encoder/recovery configuration, OAuth permissions,
Vardum artwork, marketing and native store distribution are unchanged.

Use the [0.2.3 deployment and recovery procedure](https://github.com/f-tuma/musubi/blob/main/docs/releases/0.2.3-deployment.md).
Publish with `version=0.2.7` and the full reviewed `expected_source_sha`. A
fresh tag can automatically deploy API and web. Source approval, green CI,
immutable publication and actual running observations remain separate evidence;
reconcile an uncertain publication result before another attempt.

After rollout, verify that actual task-read failures expose the bounded phase,
code and query-state fields without private content, and that successful
calendar reads continue. A specific task-recovery change needs that evidence
and its own review. Mailbox-unavailable 404s retain their separate investigation.
