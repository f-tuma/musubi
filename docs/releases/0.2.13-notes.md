# Musubi 0.2.13

## Synchronization fixes

- Concurrent provider requests sharing a synchronization worker are sequenced
  through budget admission, HTTP response headers and cooldown settlement.
  Budget waits from these dispatches no longer park a sibling's active dispatch
  or prematurely release its account and collection protection. Response body
  parsing and independent OAuth dependency waits retain their existing scope.
- Synchronization worker diagnostics retain bounded failure phase, family and
  reason information without account identifiers, provider payloads, credentials
  or raw database queries. Authority and checkpoint guards remain enforced.
- Expected provider-budget and queued-work deferrals in account/discovery
  synchronization have their own outcome and log event. They no longer inflate
  those failure counters or panels; genuine provider, network and authority
  failures remain visible. Unconfirmed delivery work retains its existing
  separate failure accounting.

## Upgrade

This is an API/web maintenance release. There are no database migrations or
client wire changes relative to 0.2.12. Client and peer minimums remain 0.2.0;
the task mutation protocol still requires clients from 0.2.2 or newer. Existing
0.2.12 mobile builds remain compatible and do not need rebuilding for these
server corrections.

The migration journal still ends at 0087 with 88 entries. Keep one active API
process and the existing provider capability and recovery settings. Do not
reset queues, weaken source/lease/checkpoint guards or replay uncertain writes
to clear historical errors. Verify new activity over a fresh Grafana interval
after deployment; historical failure counters and log entries remain history.

These notes describe the candidate source. Green source checks, artifact
publication, production deployment and subsequent provider behavior require
their own evidence. A successful deployment alone does not certify every
connected account; provider-specific mailbox availability remains separate.
