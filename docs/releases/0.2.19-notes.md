# Musubi 0.2.19

- Musubi can now save a new title, description or location for one of your
  own iCloud events, once the server operator turns this on. Until now such
  edits were refused with "Event writing is unknown. No changes were saved."
  This covers a timed, non-recurring event that has no explicit time model
  in Musubi, whether it started in iCloud or Musubi copied it there.
- The repair is **off by default**. Installing this version alone changes
  nothing; the operator must separately set
  `ICLOUD_PERSONAL_CONTENT_WRITES_ENABLED=true`. Explicit event time editing
  does not need to be turned on.
- Before each change, Musubi checks that the event is still the version it
  last saw. After the change, it reads the event back from iCloud and accepts
  only what iCloud returns. If that read-back cannot confirm the change, the
  edit is still saved in Musubi but reported as not yet confirmed (HTTP 502).
  Musubi then checks iCloud again in the background and never blindly sends the
  same write twice.
- When the event is also copied to other providers, the first attempt may
  report a provider conflict without saving anything, as in 0.2.18. In that
  case, try again explicitly once.

All-day and recurring events, events with guests or an organizer, read-only
calendars, and time, calendar or reminder changes remain unsupported for iCloud
through this path. No live iCloud acceptance of this repair exists yet.

This API/web maintenance release works with current mobile apps and needs no
database migration or new mobile build. Client and peer minimums stay 0.2.0,
and the task protocol is unchanged.
