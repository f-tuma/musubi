# Musubi 0.2.18

- Deleting or editing your own event no longer stays blocked forever when it
  is also on an Outlook, iCloud or Google calendar and that provider has
  changed only its own details for the copy. Outlook does this shortly after
  an event is created. The first attempt still reports a provider conflict
  and saves nothing. While answering it, the server re-reads the
  provider copies, so trying once more completes the change.
- If a copy really was changed in Outlook, iCloud or Google, for example its
  title or time, Musubi still refuses to edit or delete it until the change is
  resolved there.

This covers personal, non-recurring events that you created yourself in
Musubi and that Musubi copied to your provider calendars. It does not yet
cover copies of events another member created, recurring events, events with
guests, or servers with event time editing turned on. A write made within the
first moments after creating an event can still conflict once, until the next
sync. This API/web maintenance release works with current mobile apps and
needs no database migration or new mobile build. Client and peer minimums
stay 0.2.0, and the task protocol is unchanged.
