# Musubi 0.2.10 release notes

Microsoft To Do list-discovery HTTP failures now retain the actual status,
initial/next-page phase and bounded Graph error classifications. Provider
messages, status text, request identities and caught parse exceptions are not
retained. This closes the diagnostic gap after calendar discovery recognizes an
unavailable mailbox. Unknown or failed task-list inventories still fail without
authorizing removal, and Tasks failures cannot select the Events mailbox
recovery branch.

Calendar identity-proof HTTP 408, 429 and 5xx failures are now recognized as
transient failures. The read still fails and keeps its identity/completeness
guards; the next scheduled attempt can retry normally. Authentication failures,
missing resources, malformed responses and identity mismatches keep their
existing behavior. Failed-attempt metrics and account-failure alerts still
count these attempts, including when logged at warning level.

These changes do not provision a Microsoft mailbox or establish that To Do is
available for a particular account. They do not resolve the iCloud principal
alias rejection; the authorized read-only account test was deferred by its
owner. No account, grant, scope, cursor or identity guard is reset or weakened.

## Upgrade and acceptance

There is **no new database migration relative to 0.2.9**; the source journal
still ends at `0085_graph_read_coverage` (86 entries). Client and peer minimums
remain 0.2.0. Provider gates, encoder/recovery configuration, artwork and native
store distribution are unchanged.

Use the [existing deployment and recovery procedure](0.2.3-deployment.md) with
`version=0.2.10` and the final reviewed full `expected_source_sha`. Keep source
review, green checks, immutable publication and measured running revisions as
separate evidence. The existing instruction to proceed with automatic backups
is authorization, not proof of backup/restore, the runtime journal, maintenance
or replacement of old consumers. Record missing operational evidence explicitly.

After rollout, inspect the new task-list diagnostic separately from the Events
mailbox diagnostic. Confirm its actual phase/status/code and preserve the
account's failure when its resource is unavailable. A proof-request timeout
must still fail the read, with no identity acceptance or cursor advancement.
No matching logs, a change in log level or successful Tasks on other accounts
does not establish recovery of the affected account.
