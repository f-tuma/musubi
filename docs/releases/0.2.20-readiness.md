## Verified against `v0.2.19`

Checked with `git diff v0.2.19..ce557a1`:

- **Database.** Nothing changes under `packages/db/drizzle` or in
  `packages/db/src/schema.ts`; the journal still ends at `0087_project_news`.
  Better Auth 1.7.27 needs no core schema change from 1.6 (the 1.7.0–1.7.2
  `account.issuer` column was withdrawn in 1.7.3 and was never applied here).
- **Accounts.** Better Auth 1.7 keys Microsoft accounts by `oid`; stored rows
  and sync references use the 1.6 `sub`. `patches/@better-auth__core@1.7.27.patch`
  keeps `sub`, pinned by `packages/auth/src/lib/auth.test.ts`. Google and Apple
  keys are unchanged. 1.7 rejects ambiguous `(provider_id, account_id)`
  lookups and there is no unique index; the pre-deployment duplicate check is
  recorded outside this file, in
  [#426](https://github.com/f-tuma/musubi/pull/426#issuecomment-7084037876).
- **Configuration.** New optional variables, all unset/false by default:
  `DISABLE_SIGNUPS`, `SIGNUP_ALLOWED_EMAILS`, `SENTRY_DSN`, `SENTRY_WEB_DSN`,
  `SENTRY_ENVIRONMENT`, `SENTRY_TRACES_SAMPLE_RATE`, `SENTRY_URL`,
  `SENTRY_AUTH_TOKEN`, `SENTRY_WEB_PROJECT`. `SIGNUP_ALLOWED_EMAILS` without
  `DISABLE_SIGNUPS=true` stops boot.
- **Deployment.** `apps/web/Dockerfile` adds `sentry-cli` and a start command
  that uploads source maps only when `SENTRY_AUTH_TOKEN` is set.
  `docker-compose.dokploy.yml` passes the three web upload variables.
- **Types and protocol.** `packages/types` adds telemetry helpers and changes
  `PRODUCT_VERSION` (0.2.19 → 0.2.20). The wire snapshot
  `packages/types/contracts/wire.json` is unchanged; public `GET /api/v1/server`
  gains the additive `signUp` and `sentry` fields. `MIN_CLIENT_VERSION` and
  `MIN_PEER_VERSION` stay `0.2.0`; the task protocol is unchanged.
- **Mobile.** `apps/client` changes (Sentry React Native, sign-up gate UI,
  `@better-auth/expo` 1.7.27) reach users only with the next store build.
  Installed apps run the 1.6.23 Expo client against the 1.7.27 server; that
  pairing has not been exercised on a device.

## Known behaviour change

Better Auth 1.7: an email-OTP sign-in by a user whose email is unverified
deletes all of that user's linked accounts (1.6: only the password
credential). No Musubi client calls `/api/auth/sign-in/email-otp`; this must be
handled before a code-sign-in UI ships.

## Rollout

API → web, per [releasing.md](../releasing.md). No migration, so the previous
images remain a valid rollback, except that accounts or sessions created by
1.7 are not covered by any downgrade test.

Preconditions: a successful database backup from the day of deployment, tag
`v0.2.20` absent, and the publication workflow run for the exact merged main
SHA after its Quality run passes.

After deployment, verify sign-in with email/password, Google, Microsoft and
Apple, an installed mobile app, a calendar token refresh, and
`/api/v1/server` reporting 0.2.20.
