# Musubi 0.2.4 release notes

This API/web hotfix corrects Microsoft calendar delta continuation validation.
The v0.2.3 reader compared raw URL pathnames, rejecting equivalent spellings of
the same opaque calendar ID, such as a literal `=` versus `%3D`. The reader now
decodes only the calendar-ID segment once, compares it exactly with the bound
calendar ID, and preserves the provider's full continuation URL and token bytes
for pagination and saved-cursor reuse.

Origin, protocol, static route, user and calendar boundaries remain enforced.
Malformed escapes, different identities, extra path segments, credentials,
fragments and parser-repaired dot/backslash/control paths are rejected before
following the continuation or accepting the page. Unproven Graph aliases remain
unsupported. Rejected links now include structural diagnostic fields without
URLs, tokens, account/calendar IDs or credentials.

The existing fixtures reproduce the encoding failure and verify next/delta
links, saved-window/cursor reuse, safe renewal of invalid cursors and diagnostic
privacy. The v0.2.3 production incident also requires live acceptance: the
previous logs do not identify whether every rejected link used equivalent
encoding or an additional canonical alias. This release does not claim that
unobserved aliases have been accepted.

## Upgrade and remaining limits

There is **no new database migration relative to 0.2.3**. The existing journal
still ends at `0085_graph_read_coverage`. Keep both client and peer minimums at
0.2.0 and preserve the existing Core gates, encoder and recovery configuration.
API/web images do not publish a native store build. Vardum URLs and original
artwork are unchanged.

Use the [0.2.3 deployment and recovery procedure](https://github.com/f-tuma/musubi/blob/main/docs/releases/0.2.3-deployment.md)
for the same singleton, consumer, backup and recovery boundaries. Publication
uses `version=0.2.4` and the full reviewed `expected_source_sha`; the fresh tag
can automatically deploy API and web. Record the exact source, green checks,
immutable images and public/live observations separately. Do not force or
recreate an existing tag after an uncertain publication result.

After rollout, verify actual Microsoft pull completion and the new structural
diagnostics if scope rejections remain. Old mailbox-unavailable 404s, missing
skip-token 400s, CalDAV discovery/fallback warnings and long scheduler sweeps
have separate causes and are not declared resolved by this hotfix. No new
provider permissions, C07 features, delivery replay or artwork upload is part
of this release.
