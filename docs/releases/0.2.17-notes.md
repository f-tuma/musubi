# Musubi 0.2.17

- Background sync of other connected accounts can no longer take every work
  slot: one of the four regular slots stays free for event and task delivery
  and for interactive provider requests such as event writes, capability
  checks and account discovery.
- When an event write cannot start in time because the provider is busy, the
  server now answers with a retryable 503 (`provider-busy`, `Retry-After`)
  that says nothing was saved, instead of a permission refusal.
- A calendar import that stops at this point now says plainly that the
  calendar was created but holds no imported events yet.
- Timed events that span several days are drawn across every day in Month
  view, and their details name the real end date. Moving such an event across
  a clock change keeps its starting time.
- Federation connections now use only the server addresses that passed the
  network safety check.

This is not a complete performance fix. Background sync of the same account
still delays that account's own writes, and recovery work and interactive
requests share the reserved slot. Client timeouts are unchanged. This API/web
maintenance release works with current mobile apps and needs no database
migration or new mobile build. Client and peer minimums stay 0.2.0, and the
task protocol is unchanged.
