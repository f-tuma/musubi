# Musubi 0.2.3 release notes

This describes the API and `apps/web` source included in 0.2.3. Artifact
publication, production observations and native distribution are recorded
separately in the
[release readiness record](https://github.com/f-tuma/musubi/blob/main/docs/releases/0.2.3-readiness.md)
and [deployment and recovery guide](https://github.com/f-tuma/musubi/blob/main/docs/releases/0.2.3-deployment.md).

## API and web scope

- Serve the web app's favicon, Apple touch icon, social preview, notification
  icon and two logo silhouettes from public stable Vardum URLs. The adopted
  artwork is the original artwork. Logo colours still follow the theme and
  calendar pigment; loading, offline and failed-image states retain the original
  local mark. Compatible future artwork updates can use the stable assets
  without rebuilding the app, subject to browser and social caches.
- Add privacy-safe CalDAV discovery mismatch diagnostics. Strict identity,
  namespace and status checks still reject unproven responses. This is
  diagnostic coverage, not a claim that intermittent iCloud discovery has
  recovered or that new provider operations are accepted.
- Include shared calendar expansion changes: explicit consumer timezones,
  bounded recurrence projection and task date markers. Documentation records
  shared tasks, provider limits, release evidence and zoomable diagrams.
- Include C01 delivery recovery: shared finite deadlines, cancellation,
  Retry-After and bounded backoff for event/task delivery, with content-free
  provider and queue metrics. Background recovery is independent of provider
  polling by default.
- Include the C02 sync profile and C03 Graph read-coverage fences. A bounded or
  partial read no longer proves deletion outside its coverage; the first new
  Graph read replaces old cursors without rewriting historical accepted intents.
- Include C03 pinned v1 operation admission and codecs, plus the C04–C06
  storage-free Google personal content UPDATE path, durable reference host and
  shared runner. Retries preserve the accepted projection and native plan;
  malformed or unknown envelopes remain on HOLD before provider access.
- Include the first C07 Google personal DELETE slice for existing personal,
  timed, nonrecurring events. Exact target absence, conditional dispatch,
  recovery and fenced mapping acknowledgement preserve the host's authority.
  Google CREATE, Graph guarded DELETE and DAV conditional shared-runtime
  profiles remain separate gates; this slice does not complete C07 or expand
  existing provider permissions.

## Other source changes since v0.2.2

The source also contains Android Agenda/Calendar/Tasks widget rework, iPhone/iPad
WidgetKit support, shared task collection/actions, adaptive Android windows and
system-bar compatibility changes. These require new native artifacts and their
own signing, distribution and device acceptance. An API/web release does not
deliver them to installed phones. The eight private mobile assets retain their
original bytes and schema-2 frozen lock; the marketing website migration is a
separate completed workstream. See [brand assets](https://github.com/f-tuma/musubi/blob/main/docs/brand-assets.md) and
[widget documentation](https://musubi.pro/docs/guides/widgets/).

## Upgrade requirements

The API boot applies additive migration `0085_graph_read_coverage` after
v0.2.2's `0084_release_0_2_2_announcement`. It adds source generation,
checkpoint revision, read-configuration fingerprint and coverage columns, plus
account `sync_read_generation` and its lifecycle/ABA trigger. The reference
host's DELETE schema is separate and adds no further Musubi API migration.
There is no new in-app announcement migration. The wire baseline and global
client/peer minimums remain 0.2.0.

`SYNC_OPERATION_V1_ENCODER_ENABLED` defaults to `true`, as already authorized
for this source. Before admitting new v1 operations, replace every actual API,
delivery worker and custom outbox consumer with the current decoder and exact
pinned codecs. Stop old processes first; run one API replica, whose singleton
lock precedes migration and listening. Explicit `false` controls future
admission only: it neither converts nor stops already accepted v1 operations.

`EXTERNAL_DELIVERY_RECOVERY_MODE` defaults to `independent`: event/task/move
recovery runs at startup and every 15 seconds even with
`EXTERNAL_SYNC_INTERVAL_MIN=0`. Select `legacy` explicitly to retain recovery
coupled to positive polling, or `disabled` to stop background recovery. Request
wakeups remain active in every mode; these settings are not write kill switches.

The v0.2.2 task boundary remains: legacy 0.2.0/0.2.1 task writes receive 426
before saving, while compatible reads and event/calendar functions remain
available. A client implementing the v0.2.2 task protocol is still needed for
task changes. A native distribution gap and unverified live/device checks remain
operator risks; use the current web client during that gap. Preserve existing
Core gates and do not enable additional provider capabilities with this release.

Before publication, establish the actual Dokploy trigger, mutable-tag behavior,
verified backup/restore and maintenance window. The unchanged workflow publishes
both API and web as `0.2.3` **and `latest`** before creating the release tag.
Follow the [deployment and recovery guide](https://github.com/f-tuma/musubi/blob/main/docs/releases/0.2.3-deployment.md); assess rollback
against the actual journal, persisted envelopes and accepted provider effects.
The API/web pilot does not require the remaining C07 implementation, native
store distribution or a new artwork upload.
