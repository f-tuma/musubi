# Musubi 0.2.20

- Operators can close registration. With `DISABLE_SIGNUPS=true` no new account
  can be created by password, email code or Google/Microsoft/Apple sign-in,
  except addresses listed in `SIGNUP_ALLOWED_EMAILS`. With the list empty the
  clients hide "Create account". Existing accounts are unaffected. Off by
  default.
- Optional error tracking, traces, logs and cron monitoring through Rustrak or
  any Sentry-protocol server. Nothing is sent unless `SENTRY_DSN` (API) or
  `SENTRY_WEB_DSN` (browser) is set. With `SENTRY_URL`, `SENTRY_AUTH_TOKEN`
  and `SENTRY_WEB_PROJECT` the web container uploads its source maps on start.
- In dark mode, today's date in the mini calendar is now filled, so it meets
  AA contrast.
- Security updates: Better Auth 1.7.27 and patched transitive dependencies
  (Astro for the docs site, node-forge, qs, decode-uri-component, minimatch,
  KaTeX). None of the fixed advisories were exploitable in Musubi's
  configuration. Existing sessions and Microsoft, Google and Apple accounts
  keep working; nobody has to sign in again.

This API/web maintenance release works with current mobile apps and needs no
database migration or new mobile build. Client and peer minimums stay 0.2.0,
and the task protocol is unchanged. Mobile error tracking ships with the next
store build.
