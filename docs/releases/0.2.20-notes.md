# Musubi 0.2.20

- Operators can close registration. With `DISABLE_SIGNUPS=true` no new account
  can be created by password, email code or Google/Microsoft/Apple sign-in,
  except addresses listed in `SIGNUP_ALLOWED_EMAILS`. With the list empty the
  web app hides "Create account"; mobile apps do so from their next store build
  (the server refuses either way). Existing accounts are unaffected. Off by
  default.
- Federated guest accounts can no longer open a regular sign-in session, and
  accepting a federation invite now checks the invite before anything is
  created. This applies regardless of the registration setting.
- Optional error tracking, traces, logs and cron monitoring through Rustrak or
  any Sentry-protocol server. Nothing is sent unless `SENTRY_DSN` (API) or
  `SENTRY_WEB_DSN` (browser) is set. With `SENTRY_URL`, `SENTRY_AUTH_TOKEN`
  and `SENTRY_WEB_PROJECT` the web container uploads its source maps on start.
- Today's date in the mini calendar is now filled, so it also meets AA
  contrast in dark mode.
- Security updates: Better Auth 1.7.27, Astro 7.4.13 for the docs site, and
  patched transitive dependencies (node-forge, qs, decode-uri-component,
  minimatch, KaTeX). None of the fixed advisories were exploitable in Musubi's
  configuration. No sign-in change is intended: sessions are not reset and
  Microsoft accounts keep their existing key. Provider sign-in on the new
  version has not been exercised live yet.

This API/web release needs no database migration or new mobile build. Client
and peer minimums stay 0.2.0, and the task protocol is unchanged. Mobile
changes (sign-up gate, optional error reporting) reach users only with a later
store build.
