Musubi provides three **Android home screen widgets**. They share Musubi's light/dark colours, readable headers and rows, a refresh control, and a compact data-status line. Resizing changes how much content and metadata appears.

| Widget | Small size | More space |
|---|---|---|
| **Agenda** | Time and title in a scrollable list | Date, calendar, end time, and location where space permits |
| **Calendar** | Month grid with larger event dots | Full-width month grid with coloured event pills and automatic contrast |
| **Tasks** | Open task titles and due labels | More scrollable rows and calendar metadata |

<Aside type="note">
These are native `AppWidgetProvider` / `RemoteViews` surfaces written in Kotlin. An Expo module passes a versioned display snapshot from the app. Android redraws that stored data; the widget does not independently contact your server.
</Aside>

## Add a widget

<Steps>
1. Long-press an empty area of the Android home screen.
2. Open **Widgets** and find **Musubi**.
3. Drag **Musubi Agenda**, **Musubi Calendar**, or **Musubi Tasks** onto the home screen.
4. Resize it to choose the compact or detailed presentation.
</Steps>

If a newly added widget asks you to open Musubi, open the app and let it load your account. Calendar/events and tasks hydrate independently. A failed load does not replace useful cached data with an ordinary empty result.

## Use the Agenda widget

- Scroll the event list when there are more rows than fit.
- Tap **+** to create an event in Musubi. The next timed event has a subtle raised background; each row uses one calendar-colour stripe.
- Recurring series are expanded, so every upcoming occurrence appears separately.
- All-day events use **All day**. Today is named in the header; future rows retain their date.
- Wider rows add the end time and location when available.
- Tap an event to open the Agenda tab with that exact occurrence's detail sheet already open.
- Task start/deadline markers open the canonical task's detail instead of an event editor.

The persisted snapshot retains covered occurrences beyond the first day's rows. Expired events are removed from the native list without requiring another app projection. If projection or display limits leave more items available in the app, the status line says **More in Musubi**.

## Use and filter the Calendar widget

- The header shows the month and full year; narrow or large-text variants abbreviate the month. Tap **+** to create an event.
- Tap a day to open Musubi at that date. A short accent ripple confirms the press before the app opens.
- Compact sizes show event colours as dots. Tall sizes use the same coloured event pills as the app.
- The number of visible pills is calculated from the actual height available to each week row; overflow is shown when it fits.
- Pill text automatically switches between dark and light ink for contrast.
- Tap the **three-dot menu** in the header to open **Widget calendars**.
- Tap calendar pills to show or hide them. Long-press a pill to show only that calendar. **Show all** resets the selection.

Calendar visibility is stored **per widget instance**. Filtering one Calendar widget does not change the Home/Agenda filters in Musubi or another widget on the same launcher.

## Use and filter the Tasks widget

- The list includes **Needs action** and **In progress** tasks; completed and cancelled tasks are excluded.
- Taller widgets show **Overdue**, **Today**, and **Later** groups. Low widgets omit group headings to leave room for tasks. Priority, title, and canonical ID break ties; undated tasks follow dated tasks.
- Each canonical task appears once even when it is readable through several calendars. An independent copy remains a separate task.
- Tap a row to open its task detail. Tap its **circle** to request completion in Musubi. A **lock** means the task is read-only; tapping it opens details. The app reads current access and task state before saving.
- The **+** opens the task creator. A small shared icon identifies tasks linked to more than one calendar.
- Tap **All calendars**, **Selected calendars**, or the **three-dot menu** to choose calendars for that Tasks widget instance. Its selection is separate from the app's filters and other widgets.

The header opens Tasks and shows the open-task count when space permits. Tasks are cached for the current server/account, so previously loaded rows can appear on a cold offline launch. An authoritative removal, authorization loss, or account/server reset clears data that is no longer readable.

## Read the data status

The status line describes the data, rather than the last time Android repainted the widget.

| State | Meaning and action |
|---|---|
| **Updated …** | Time of the last successful sync for that section |
| **Cached on this device** | Local data is available without a recorded successful sync time |
| **Could not update · cached data** | A failed update retained usable data; use refresh to retry in Musubi |
| **More in Musubi** | A snapshot or list limit prevented the widget from showing every item |
| **Timezone changed** / **Dates need updating** | Open Musubi to rebuild timezone-dependent data or load fresh date coverage |
| A load or reload prompt | The snapshot is missing, invalid, unsupported, or unavailable; open Musubi |
| **Sign in to Musubi** | Private content was cleared on sign-out |

**Nothing ahead** and **No open tasks** are successful empty results. A failed expansion, expired coverage, or an incomplete snapshot uses a load/update prompt instead of claiming that nothing exists.

## When widgets refresh

The refresh control opens Musubi and starts the app's authenticated refresh. It needs the normal server connection and session. Widgets otherwise redraw the persisted snapshot through several paths:

| Trigger | What happens |
|---|---|
| Relevant event, calendar, task, sync-status, or display-setting data changes while Musubi is running | The app rebuilds its snapshot after a 120 ms debounce; identical projections are skipped |
| Refresh control or load prompt is tapped | Musubi opens and refreshes that view through the app's normal sync |
| Calendar selection changes in **Widget calendars** | That widget instance is updated immediately |
| Widget is resized | Android calls `onAppWidgetOptionsChanged`; the adaptive layout is recalculated |
| Date, time, timezone, or locale changes | Native providers redraw stored data; incompatible timezone data requests an app rebuild |
| Musubi returns to the foreground, or the active app notices midnight/a changed timezone | The app rebuilds the snapshot and its civil-date buckets |
| Periodic launcher update | Android may call the providers to redraw; the configured 30-minute interval does not guarantee an exact update time |
| Sign-out or account/server reset | Lifecycle fences reject obsolete writes; private event/task data and account-specific widget selections are cleared |

Calendar coverage runs from the previous month through the same calendar month in the following year. Native date changes can advance the current month within valid stored coverage. They cannot expand new floating occurrences, rebucket timed events in a new timezone, or fetch server changes. Open Musubi when the widget requests an update. Closed-app network freshness and exact midnight updates are not guaranteed.

      - MusubiCalendarWidgetProvider.kt — adaptive month grid, dots, pills, and deep links
      - AgendaWidgetData.kt — snapshot parser and date/time formatting

  - src/widget-tokens.ts — shared widget appearance contract
  - src/android-widget.ts — native colour/dimension resource adapter
  - scripts/generate-css.ts — generates both widget themes with the web tokens
</FileTree>

Completion tickets contain scope, canonical task ID, revision, and provider-read retirement generation. They are single-use, expire after 24 hours, and are cleared on account/server change or sign-out. They authorize only a request: Musubi verifies fresh home-calendar rights and conditional revision/retirement fences through the normal task API. Completion needs a working connection; the widget does not toggle offline state.

The v2 snapshot contains display fields and an account/server scope, lifecycle/generation, section freshness, coverage, completeness, readable calendar IDs, occurrence keys, and canonical task IDs. Credentials do not belong in widget snapshots or preferences. Event and task sections can fail independently; explicitly retained rows keep their original freshness and timezone.

Storage budgets are explicit: at most 4,096 projected events, 2,048 tasks, 32,768 day references, and 1 MiB of newly projected UTF-8 JSON. Recurrence expansion shares a limit of 50,000 candidates and 10,000 results across families, including candidates before coverage and exclusion rules. Native storage allows up to 2 MiB when retaining independently valid cached sections. It prunes inaccessible memberships before trimming rows to that ceiling. The native scrollable collections expose at most 128 rows. Budget exhaustion marks coverage incomplete; it is not a successful empty result. All-day bars retain their true endpoints while reference iteration stays inside coverage.

Widget projections support daily, weekly, monthly, and yearly recurrence. Unsupported subdaily rules produce an update error rather than an empty agenda.

Widget deep links route through Expo Router:

- Agenda event → `musubi://agenda?eventId=…&occurrenceStart=…`
- Calendar day → `musubi:///?time=…`
- Calendar picker → `musubi:///?calendarWidgetId=…`
- Task detail, including Agenda task markers → `musubi://tasks?taskId=…`
- Tasks picker → `musubi://tasks?tasksWidgetId=…`
- New task/event → `musubi://tasks?widgetAdd=1` / `musubi:///?widgetAdd=1`
- Completion request → `musubi://tasks?taskId=…&widgetComplete=…` (native single-use ticket, never credentials)
- Refresh → `musubi://agenda?widgetRefresh=1`, `musubi:///?widgetRefresh=1`, or `musubi://tasks?widgetRefresh=1`

Cold-start routing preserves parameters until scoped data hydrates. Agenda redirects to Home's Agenda view while retaining occurrence/refresh parameters; task links use the canonical task ID.

## Install a local widget build

Widget providers, manifests, Kotlin, XML layouts, drawables, and resource changes are **native changes**. Metro refresh is not enough; build and replace the APK:

```sh
cd apps/client/android
./gradlew :app:assembleDebug --no-daemon
cd ../../..
adb install -r apps/client/android/app/build/outputs/apk/debug/app-debug.apk
```

The `-r` flag preserves app data and existing widget instances. A pure TypeScript snapshot or modal change still needs the normal app bundle/dev server, but does not require changing widget registration. Generate token resources before building after a design-token change:

```sh
pnpm --filter @musubi/design-system generate
pnpm --filter @musubi/design-system test
```

`values/musubi_widget_tokens.xml` and `values-night/musubi_widget_tokens.xml` are generated. Edit their TypeScript sources instead. Android receives `#AARRGGBB` colours, `dp` geometry, and scalable `sp` type. RemoteViews uses system serif/sans fallbacks; device QA must verify their optical result and font scaling.

<Aside type="caution">
Android launchers may reapply a `RemoteViews` update onto a cached tree when the same layout resource ID is reused. If the widget hierarchy changes, give the layout a new resource name and update the provider metadata. This avoids a stale tree producing **Can't load widget** after an APK replacement.
</Aside>

## Focused test checklist

- Add all three widgets, then resize each through compact and detailed sizes, landscape, and larger font scales.
- Confirm recurring events appear as separate Agenda rows and Calendar occurrences.
- Scroll the Agenda and open both a normal event and a recurring occurrence.
- Tap a Calendar day and confirm the press feedback and selected date in Musubi.
- Open a task from Tasks and an Agenda task marker; confirm canonical detail. Check circle completion with current edit rights, lock behavior on read-only mirrors, stale revision rejection, offline failure, and repeated/switch-account links.
- Hide one calendar in Calendar and Tasks; confirm only the configured widget changes.
- Switch Android between dark and light without resizing the widget; day numbers must remain readable.
- Check TalkBack names, press targets, scrolling, and focus after returning from the app.
- Check cold offline launch, failed sync, missing/invalid data, incomplete coverage, timezone/DST changes, and expired coverage.
- Sign out and switch account/server; confirm private content and old account selections disappear, including delayed writes.
- Record launcher/version, sizes, theme, steps, and screenshots. Logic tests and a native build do not establish physical-device acceptance.

## iOS status

The current module is Android-only. iOS is a separate later project requiring a WidgetKit extension, shared-container storage, timeline/refresh policy, signing, and device verification. No iOS widget dependency or closed-app refresh behavior is established by this Android implementation.
